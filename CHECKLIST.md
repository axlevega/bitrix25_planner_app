## Перепланирование ПМ: исходный план vs скорректированный план (без ретроспективы)

ПМ может менять плановую нагрузку по дням и сроки задачи. В сетке различаем: исходное планирование (B24), скорректированный план (редактируемый), факт. Ретроспективу не делаем.

### Этап 1: Backend — модель данных и API
- [x] Миграция **task_plan_override**: bitrix24_task_id (UK), plan_start_date, plan_end_date, original_plan_start, original_plan_end, original_time_estimate, updated_at
- [x] Миграция **task_plan_daily**: bitrix24_task_id, plan_date, planned_hours, updated_at; UK (task_id, plan_date)
- [x] API GET task-plan (bitrix24_task_id): исходный план (из override или B24), переплан (даты + часы по дням)
- [x] API PUT task-plan: сохранение переплана; при первом сохранении — снимок original_* из B24
- [x] planning-grid: для каждой задачи отдавать plan_hours_by_date (из task_plan_daily или авто), original_plan_hours_by_date (при наличии override), has_plan_override

### Этап 2: Фронт — заливка ячеек и три типа строк
- [x] Исходный план — светло-зелёная заливка ячеек
- [x] Скорректированный план — светло-голубая заливка
- [x] Факт — светло-оранжевая заливка
- [x] При наличии переплана: строка плана показывает переплан (исходный план не выводится отдельной строкой); две подстроки (план/переплан и факт)

### Этап 3: Фронт — редактирование переплана
- [x] Открытие формы переплана по задаче (клик / кнопка)
- [x] Блок «Исходный план» (только чтение): даты и оценка из B24 (или снимок)
- [x] Блок «Переплан»: даты начала/окончания, таблица дней с редактируемыми часами
- [x] Сохранение через PUT task-plan

### Этап 4: Переплан с разрывами (интервалы)
